## Analysis

- The prescriptions listing executed **3** statement(s) for 5 rows. Without `@EntityGraph` (`PrescriptionRepository`'s 2-hop lazy chain: `Prescription` -> `Appointment` -> `Patient`/`Doctor`, all `@ManyToOne(LAZY)`), each row's own `toResponse` mapping would have fired 3 extra `SELECT`s — roughly **1 + 5 x 3 = 16** statements for the same 5 rows, scaling linearly with row count. This run's count does not scale with row count at all.
- `GET /api/v1/patients/{id}` executed **9** statement(s) across its 9 independent finder calls (`PatientService.getPatient`) — one per finder, each now carrying its own `@EntityGraph`, instead of each finder's own per-row lazy fan-out (`toReferralResponse` alone would otherwise cost 3 extra selects per referral row).
- Both counts stay flat regardless of row count — the defining signature of an N+1 fix, as opposed to a count that grows with the data.
