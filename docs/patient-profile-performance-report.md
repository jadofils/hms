"Before" is measured for real — the same 9 methods, called sequentially through the real Spring-managed `PatientService` bean, not a projected number. "After" is the real `GET /api/v1/patients/{id}` endpoint, which already runs the parallel version.

## Analysis

- The parallel version was **1.47x faster** than running the same 9 lookups sequentially, on this run.
- The parallel measurement includes real HTTP + Spring MVC dispatch overhead the sequential measurement doesn't (a direct method call) — the true fan-out speedup on the 9 lookups themselves is understated here, not overstated.
- Every one of the 9 lookups also carries its own `@EntityGraph` (HMS v5's first change this pass) — this benchmark measures the fan-out's own effect on top of that fix, not a combined before/after against the pre-`@EntityGraph` state.
